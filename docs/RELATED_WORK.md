# RELATED_WORK — 선행연구·관련 도구와의 관계

TAP-LegalRAG의 차별점은 **검색 성능**이 아니라, 찾은 근거로 *답해도 되는지*를 판정하는 **검증 게이트(P·T·A)**를 부품으로 분리해 그 효과를 측정한 데 있다. 아래는 관련 흐름과의 위치 관계다.

## 1. RAG의 사실성·인용 검증 흐름
- **RAG / FiD류**(Lewis 2020 등): 검색된 문서로 답을 생성. TAP는 생성 이전 단계, 즉 "이 근거로 답해도 되는가"를 판정하는 **게이트**에 집중한다(생성층은 v1.3).
- **Attribution / citation faithfulness**(예: 답변-인용 일치 평가): 생성된 답이 근거에 충실한지를 사후 검증. TAP는 이를 **사전**으로 옮겨, 인용 자체가 코퍼스의 실제 조문으로 해석되는지(P)와 시점(T)·적용대상(A)을 먼저 본다.
- **Selective prediction / abstention**(모르면 답하지 않기): TAP의 ABSTAIN·CONFIRM 경로가 이 계열이다. 차이는 법령 도메인 특유의 보류 사유(출처 미확정·낡은 번호·기관유형 의존)를 **명시 규칙**으로 분해해 측정한다는 점.

## 2. 법률·규정 QA 도메인
- **법률 QA / 판례 검색 연구**: 대체로 검색·순위 또는 생성 품질을 겨룬다. TAP는 "답 가능성 판정"을 독립 지표(오귀속률·잘못된 보류율·답변 불가 문항 ANSWER 선택률)로 보고한다.
- **시점(temporal) 법령 처리**: 법은 개정되므로 '언제 기준의 조문인가'가 핵심이나, 과거 전 판본 엔진은 비용이 크다. TAP는 전 판본 엔진이 **아니며**, 소수 대표 사례의 수작업 계보로 '낡은 번호 인용'만 탐지하는 한정판이다(한계는 [LIMITATIONS](LIMITATIONS.md)).

## 3. 국가연구개발 규정 MCP 도구
### korean-rnd-regs-mcp (smilemin07, Apache-2.0)
[github.com/smilemin07/korean-rnd-regs-mcp](https://github.com/smilemin07/korean-rnd-regs-mcp) — 국가연구개발 법령·행정규칙 66종과 혁신법 매뉴얼을 국가법령정보 OpenAPI로 **검색·조회**하고, 조문의 **개정 이력·신구조문·시행일 차이**까지 제공하는 규정 검토용 MCP 서버.

TAP와의 관계는 **경쟁이 아니라 역할 분담**이다. 비유하면 그 도구는 서가에서 해당 조문을 **찾아 주는 사서**, TAP는 그 조문으로 **답해도 되는지 따지는 검수자**다. TAP는 근거를 찾아 주는 일을 대신하지 않고, 찾은 근거의 답 가능성 판정을 켜고 끌 수 있는 부품으로 분리해 측정한다. 함께 쓰는 구성은 [ROADMAP](ROADMAP.md) v1.2에서 실험한다. (그 프로젝트를 "단순 검색"으로 표현하지 않는다. 코드·데이터는 복사하지 않고 링크·설명만 둔다.)

### Korean Law MCP 류 (국가법령정보 OpenAPI 기반 일반 MCP)
국가법령정보 OpenAPI를 감싸 법령 본문·조문을 제공하는 범용 MCP들이 있다. 이들은 **조문 제공(소스)** 계층이며, TAP의 **판정(게이트)** 계층과 상보적이다. TAP는 이들을 근거 소스로 받아 P·T·A를 적용하는 소비자가 될 수 있다(에이전트 연계: [AGENT_USAGE](AGENT_USAGE.md), v1.2).

## 요약 위치
| 계층 | 대표 | TAP의 위치 |
|---|---|---|
| 조문 소스·검색 | korean-rnd-regs-mcp, Korean Law MCP | 소비자(근거를 받음) |
| 답 생성 | RAG/FiD/LLM | 미구현(v1.3) |
| **답 가능성 판정** | (본 연구) | **핵심 기여: P·T·A 게이트 + 측정** |
| 사실성 사후검증 | attribution/faithfulness | 사전 판정으로 이동 |
