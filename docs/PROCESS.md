# PROCESS — 평가 동결·재현성·정직성 원칙

이 프로젝트의 운영 원칙은 하나로 요약된다: **점수를 올리려고 튜닝하지 않는다. 원인을 정직하게 찾고, 개선되지 않은 지표도 지우지 않는다.**

## 1. 평가 동결

- 채점 사양은 [EVAL_SPEC_v1](../specs/EVAL_SPEC_v1.md)에 **동결**한다. 이후 모든 결과표는 이 사양으로 재현된다.
- 채점 대상 집합·지표 정의·주소 매칭 규칙·분모를 먼저 글로 적고, 그다음 측정한다. 숫자가 나온 뒤 유리하게 집합을 고르지 않는다.
- **설계에 쓴 문항 제외 목록은 실행 전에 기록**한다(EVAL_SPEC §11, 근거: 비공개 내부 계획 문서, 2026-10-07 작성). 사후 선택이 아님을 증명하기 위함.

## 2. 재현성

- 모든 평가·진단 산출물에 **RunManifest** 첨부: `run_id·timestamp·golden_sha256·corpus_sha256·code_commit+dirty·eval_spec_version·retriever_config_hash·seed`.
- 평가 하니스는 `--out`이 주어질 때만 파일을 쓴다(문서 덮어쓰기 부작용 제거). 기본 실행은 표준출력만.
- 같은 설정 2회 실행 시 결과 파일 해시 동일(결정성 확인).
- 문서 속 모든 핵심 수치는 `scripts/sync_numbers.py`가 결과 JSON과 **자동 대조**한다. 다르면 테스트 실패 → 문서가 결과를 앞지를 수 없다.

## 3. 정직성 규칙

- **개선되지 않은 지표를 삭제하지 않는다.** 예: 게이트가 결정 정확도를 B0보다 낮춘다는 사실, P·T가 이 벤치마크에서 순이득이 아니라는 사실을 그대로 보고한다.
- **착시 지표를 표시한다.** "다 답하기"만으로 결정 정확도 0.846이 나오는 점을 매번 명시.
- **과장 금지어**: '최초'·'검증 완료'·'환각 감소'·'보안 검증'을 쓰지 않는다. 사람 검수 부분집합을 "독립 검증된 테스트셋"이라 부르지 않는다.
- **라벨 출처 명시**: 골든·P 정답표는 LLM(작업보조 LLM) 작성 + 교차검토. 사람 독립 검수는 표시된 문항만.
- **버그를 숨기지 않는다.** rc1→rc2→rc3의 수정 이력과 각 변화가 만든 오답까지 [RESULTS](RESULTS.md)·[CHANGELOG](CHANGELOG.md)에 남긴다. 이전 rc 수치는 보존한다.

## 4. 변경 규율

- 테스트 기대값을 고쳐서 통과시키지 않는다. 바꿔야 하면 근거를 spec에 먼저 적고 계약으로 반영한다.
- 작은 단위로 커밋(결함 하나 = 커밋 하나), 한국어 메시지.
- 커밋 전 PII 스캔(pre-commit 훅). `.gitattributes`로 바이트 보존.

## 5. 왜 이렇게까지 하나

연구행정 자동화의 핵심은 답을 빨리 찾는 게 아니라 **답해도 되는지 판단하고, 모를 때 사람에게 넘기는 구조**다. 그 구조를 측정하려면 측정 자체가 정직해야 한다. 점수에 맞춰 집합·지표·문구를 움직이면, 정작 "멈춰야 할 때 멈추는가"를 잴 수 없게 된다.
